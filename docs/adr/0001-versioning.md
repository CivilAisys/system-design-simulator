# 版號用 0.x 起跳，和開發階段、API、檔案格式的版本分開

ROADMAP 的開發階段原本叫 v1／v2／v3，但第一階段完成時的功能還稱不上正式版，所以第一個 release 是 `v0.1.0`，不是 `1.0.0`。為了不讓「v1」被誤讀成 1.0.0，ROADMAP 的大版本改叫**階段一／二／三**，和版號脫鉤。

## 規則

- **應用程式版號**（`main` 上的 git tag，同步寫進 `frontend/package.json` 和 `backend/build.gradle.kts`）採用 SemVer 的 `0.y.z`：
  - **minor**：累積一批可以完整操作的新功能就升一次，例如 `0.2.0`。0.x 期間 minor 可以包含不相容的改動。
  - **patch**：只修 bug，行為和格式不變，例如 `0.1.1`。
  - **`1.0.0`**：標準以後再訂。訂好之前一律留在 0.x。
- **API 路徑**（`/api/v1`）和**拓撲檔格式**（JSON 的 `"version": 1`）是各自獨立的介面版本，只在它們本身不相容時才升，不跟著應用程式版號跳。拓撲檔升版時，匯入要能遷移舊版檔案，使用者的存檔不能失效。
- **開發階段**（階段一、二、三）只描述 ROADMAP 的方向，一個階段可能跨好幾個 minor 版本。
- **GitHub milestone** 用目標版號命名，例如 `0.2.0`。

`docs/v1-spec.md` 保留原檔名：已經有很多 issue 連到這個路徑。檔案內容是階段一的規格。
